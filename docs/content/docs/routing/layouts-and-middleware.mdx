Layout files in Taser allow you to organize cross-cutting concerns (authentication, CORS, rate limiting, logging) and inject typed state into child routes without repeating code in every handler.

---

## What is a Layout File?

A layout file is any TypeScript file inside `src/routes/` that does not end with an HTTP method. It exports a `Middleware` constant initialized with `t.middleware(layoutId)`.

```ts title="src/routes/admin.ts"
import { reply } from "@taserjs/router";
import { t } from "#taserjs/router";

export const Middleware = t.middleware("admin").use(async (ctx, next) => {
  const authHeader = ctx.headers.get("authorization");
  if (!authHeader?.startsWith("Bearer ")) {
    return reply.unauthorized({ message: "Admin authorization required" });
  }

  const token = authHeader.slice(7);
  const adminUser = await verifyAdminToken(token);
  if (!adminUser) {
    return reply.forbidden({ message: "Insufficient permissions" });
  }

  // Injects adminUser directly into ctx.state for all downstream routes
  return next({ adminUser });
});
```

All route files in `src/routes/admin/` (or `src/routes/admin.*.ts`) automatically inherit this middleware and receive `ctx.state.adminUser` fully typed.

## Root Layout (`src/routes/$.ts`)

The root layout applies to every route in your application. It is the ideal place for global concerns like CORS, security headers, request timing, and tenant resolution:

```ts title="src/routes/$.ts"
import { cors } from "@taserjs/router/cors";
import { secureHeaders } from "@taserjs/router/secure-headers";
import { timing } from "@taserjs/router/timing";
import { t } from "#taserjs/router";

export const Middleware = t
  .middleware("/$")
  .use(
    cors({
      origin: ["https://app.example.com", "https://admin.example.com"],
      credentials: true,
    }),
  )
  .use(secureHeaders())
  .use(timing());
```

---

## Root Index Layout (`src/routes/index.ts`)

While `src/routes/$.ts` applies globally to every route in your application, `src/routes/index.ts` is scoped specifically to root index endpoints (such as `src/routes/index.get.ts`). It mounts with `t.middleware('index')`:

```ts title="src/routes/index.ts"
import { t } from "#taserjs/router";

export const Middleware = t.middleware("index").use(async (_ctx, next) => {
  // Only runs for the root '/' endpoint
  return next();
});
```

Nested directory index files (e.g. `src/routes/admin/index.ts`) similarly mount with `t.middleware('admin/index')` and execute only for `GET /admin` (`src/routes/admin/index.get.ts`).

## Injecting Typed State

When middleware calls `next({ session })`, the properties merge directly into `ctx.state`. Downstream handlers access these properties with complete TypeScript inference:

<Tabs items={["Middleware", "Route Handler"]}>
  <Tab value="Middleware">
    ```ts title="src/routes/dashboard.ts"
    import { reply } from "@taserjs/router";
    import { t } from "#taserjs/router";

    export const Middleware = t.middleware("dashboard").use(async (ctx, next) => {
      const session = await getSession(ctx.headers.get("cookie"));
      if (!session) {
        return reply.unauthorized({ message: "Invalid session" });
      }

      return next({ session });
    });
    ```

  </Tab>
  <Tab value="Route Handler">
    ```ts title="src/routes/dashboard/metrics.get.ts"
    import { reply } from "@taserjs/router";
    import { t } from "#taserjs/router";

    export const Route = t.get("/dashboard/metrics").handler(async (ctx) => {
      // ctx.state.session is 100% typed from dashboard.ts:
      const { userId, workspaceId } = ctx.state.session;

      const metrics = await ctx.db.getWorkspaceMetrics(workspaceId);
      return reply.json({ userId, metrics });
    });
    ```

  </Tab>
</Tabs>

## Standalone Middlewares with `defineMiddleware`

To create reusable, type-safe middlewares across layout files or projects, use `defineMiddleware()`:

```ts title="src/middleware/rate-limit.ts"
import { defineMiddleware, reply } from "@taserjs/router";

export function rateLimiter(options: { maxRequests: number; windowSeconds: number }) {
  return defineMiddleware(async (ctx, next) => {
    const clientIp = ctx.headers.get("x-forwarded-for") ?? "127.0.0.1";
    const remaining = await checkRateLimit(clientIp, options);

    if (remaining <= 0) {
      return reply.badRequest({ message: "Rate limit exceeded" });
    }

    return next({ rateLimitRemaining: remaining });
  });
}
```

### App-Bound Middlewares (`t.defineMiddleware`)

When creating middlewares within your application, use `t.defineMiddleware` from your initialized router instance (`t`). It automatically inherits your application's boot and request context (`ctx.db`, `ctx.requestId`, etc.) with zero manual type annotations:

```ts title="src/middleware/tenant-logger.ts"
import { reply } from "@taserjs/router";
import { t } from "#taserjs/router";

export const tenantLogger = t.defineMiddleware(async (ctx, next) => {
  // ctx.db and ctx.requestId are 100% typed from your taser.context definition!
  ctx.db.logTenantAccess(ctx.requestId);
  return next();
});
```

<Callout type="info">
  Use **`t.defineMiddleware`** for application-specific middlewares that interact with your
  database, loggers, or app context. Use the global **`defineMiddleware`** from `@taserjs/router`
  when building standalone, shareable npm middleware packages.
</Callout>

## Layout-Scoped Middlewares

When creating middleware tailored for a specific route hierarchy, pass the layout identifier as the first argument to `defineMiddleware()`.

### 1. Single Layout Binding

Passing a layout identifier binds the middleware directly to that layout branch:

```ts title="src/middleware/user-guard.ts"
import { defineMiddleware, reply } from "@taserjs/router";

export const requireActiveUser = defineMiddleware("users", async (ctx, next) => {
  // 1. ctx.state automatically inherits all state provided by the "users" layout chain:
  const user = ctx.state.user;

  if (!user.isActive) {
    return reply.forbidden({ message: "User account suspended" });
  }

  // 2. Injects additional state downstream:
  return next({ userTier: user.tier });
});
```

#### Compile-Time Branch Safety

TypeScript guarantees that `requireActiveUser` can only be attached to routes or layouts under the `"users"` branch:

```ts title="src/routes/users/settings.get.ts"
import { reply } from "@taserjs/router";
import { t } from "#taserjs/router";
import { requireActiveUser } from "../../middleware/user-guard";

// Allowed: Route inherits "users" layout
export const Route = t
  .get("/users/settings")
  .use(requireActiveUser)
  .handler((ctx) => {
    return reply.json({ tier: ctx.state.userTier });
  });
```

If you attempt to mount it on an unrelated branch, TypeScript emits an immediate compile error:

```ts title="src/routes/posts/$id.get.ts"
// ❌ TypeScript Error: Cannot attach middleware scoped to "users" layout on "posts" branch
export const Route = t
  .get("/posts/:id")
  .use(requireActiveUser)
  .handler((ctx) => reply.ok());
```

---

### 2. Multi-Layout Binding (Branch Union)

If a middleware applies to multiple distinct layout branches (such as both `"dashboard"` and `"admin"`), pass an array of layout IDs:

```ts title="src/middleware/tenant-guard.ts"
import { defineMiddleware, reply } from "@taserjs/router";

export const requireTenant = defineMiddleware(["dashboard", "admin"], async (ctx, next) => {
  // ctx.state receives the common state guaranteed across all specified layouts:
  const session = ctx.state.session;

  if (!session.tenantId) {
    return reply.forbidden({ message: "Tenant required" });
  }

  return next({ tenantId: session.tenantId });
});
```

This middleware can now be safely attached to routes inheriting either the `"dashboard"` or `"admin"` layout branches with total type safety.

## State-Requirement Generics (`defineMiddleware<TState, TRequires>` / `.requires<TState>()`)

> [!TIP]
> **Generics Order: Output First, Precondition Second**
> `defineMiddleware<TState, TRequires>((ctx, next) => ...)` or `defineMiddleware().requires<TRequires>().handler(...)`
>
> - **1st generic (`TState`)**: What this middleware **produces** / passes downstream via `next(state)`.
> - **2nd generic (`TRequires`)**: What this middleware **requires** / enforces on `ctx.state` before running.

For un-scoped middlewares that are not tied to a specific layout name but still require certain properties to exist in `ctx.state`, use the `.requires<TRequires>()` fluent builder method or generic parameters:

```ts title="src/middleware/admin-guard.ts"
import { defineMiddleware, reply } from "@taserjs/router";

type RequiredState = {
  user: {
    id: string;
    role: "admin" | "superadmin" | "user";
  };
};

export const requireAdmin = defineMiddleware()
  .requires<RequiredState>()
  .handler(async (ctx, next) => {
    // ctx.state.user is guaranteed by TypeScript to exist:
    if (ctx.state.user.role !== "admin" && ctx.state.user.role !== "super-admin") {
      return reply.forbidden({ message: "Administrator privileges required" });
    }

    return next({ isAdmin: true });
  });
```

### Compile-Time Precondition Validation

When `.use(requireAdmin)` is added to a route or layout, TypeScript inspects the preceding middleware chain. If an upstream layout has not already injected `{ user: { ... } }`, TypeScript flags an error:

```ts
// ❌ TypeScript Error: Route state does not satisfy RequiredState { user: ... }
t.get("/unprotected").use(requireAdmin);

// Allowed: Upstream auth middleware provides { user: ... }
t.get("/protected")
  .use(authenticateUser)
  .use(requireAdmin)
  .handler((ctx) => {
    return reply.json({ isAdmin: ctx.state.isAdmin });
  });
```
