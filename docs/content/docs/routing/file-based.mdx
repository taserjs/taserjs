Taser routes are TypeScript files. The file name decides the HTTP method and the URL path. This makes APIs easier to grow because the filesystem is the source of truth.

## Route files vs layout files

Under `src/routes/` you will create two kinds of files:

- **Route files** end with an HTTP method, like `hello.get.ts` or `users.post.ts`. They export `Route`.
- **Layout files** end with `.ts` and do not include a method suffix. They export `Middleware`.

Layout files let you compose shared behavior like auth, state, and validation for a whole group of routes.

## Method suffixes

The method comes from the file suffix:

- `*.get.ts` -> `GET`
- `*.post.ts` -> `POST`
- `*.put.ts` -> `PUT`
- `*.patch.ts` -> `PATCH`
- `*.delete.ts` -> `DELETE`
- `*.options.ts` -> `OPTIONS`
- `*.head.ts` -> `HEAD`

## Directory routes

Directories map directly to URL segments:

```
src/routes/account/overview.get.ts  ->  GET /account/overview
src/routes/settings/profile.get.ts ->  GET /settings/profile
```

## Index routes

`index` is special. It is treated as the directory root:

```
src/routes/index.get.ts      -> GET /
src/routes/todo/index.get.ts -> GET /todo
```

## Params with `$id`

A `$name` segment becomes a path param in the URL:

```
src/routes/users/$id.get.ts    -> GET /users/:id
src/routes/posts.$id.get.ts    -> GET /posts/:id
src/routes/posts_.$id.edit.get.ts -> GET /posts/:id/edit
```

Inside your handler, `ctx.params.id` is typed:

```ts
import { reply } from "@taserjs/router";
import { t } from "../taser";

export const Route = t.get("/users/:id").handler((ctx) => {
  return reply.json({ id: ctx.params.id });
});
```

## Splats with `$`

A `$` segment becomes a splat:

```
src/routes/files/$.get.ts -> GET /files/*
```

Use this for file serving, proxy routes, or any endpoint where the remainder of the path is part of the request.

## Pathless segments with `_public`

Segments that start with `_` (and do not end with `_`) are pathless. They do not appear in the URL.

This is useful for layouts that group behavior without changing the public API surface:

```
src/routes/_public.ts            -> layout for public routes
src/routes/_public.health.get.ts -> GET /health
```

In that example, `_public` is not part of the URL, but its middleware still runs for `/health`.

## Grouping segments with `posts_`

Segments that end with `_` are kept in the URL, but the underscore is removed:

```
src/routes/posts_.ts        -> layout for /posts
src/routes/posts_.$id.get.ts -> GET /posts/:id
```

This naming is handy when you want a layout file next to routes that share a prefix, without using a directory.

## How it is wired at runtime

When you run `taser generate` or `taser watch`, Taser writes a `routeManifest.gen.ts` file. Your server imports that manifest and creates the app:

```ts
import { routeManifest } from "./routeManifest.gen";
import { t } from "./taser";

export const app = t.create(routeManifest);
```

The manifest is a build artifact. Your source of truth is still the route files.
