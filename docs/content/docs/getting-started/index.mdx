The quickest way to get started with Taser is using the official `create-taserjs` scaffolding tool. It generates a pre-configured, production-ready project with TypeScript, hot-reloading, route watching, and your choice of tools.

---

## Prerequisites

Before creating a project, make sure your development environment meets these requirements:

- **Node.js**: Version `20.19.0` or higher
- **Package Manager**: `npm`, `pnpm`, `yarn`, or `bun`
- **TypeScript**: Version `5.0` or higher

---

## Create a New Project

<Steps>
  <Step>
    ### Run the Scaffolding Command

    Run the interactive initializer in your terminal:

    <Tabs items={["npm", "pnpm", "yarn", "bun"]}>
      <Tab value="npm">
        ```bash
        npm create taserjs@latest
        ```
      </Tab>
      <Tab value="pnpm">
        ```bash
        pnpm create taserjs@latest
        ```
      </Tab>
      <Tab value="yarn">
        ```bash
        yarn create taserjs
        ```
      </Tab>
      <Tab value="bun">
        ```bash
        bun create taserjs@latest
        ```
      </Tab>
    </Tabs>

  </Step>

  <Step>
    ### Choose Your Stack

    The interactive wizard will guide you through selecting your preferred tools:

    1. **Project Name**: Enter a directory name (for example, `my-taser-api`).
    2. **Host Framework**:
       - **None (Standalone)**: Pure Taser with high-performance virtual routing and zero host overhead.
       - **Hono**: Lightweight, ultra-fast web standard framework for Node and edge.
       - **Express**: Battle-tested Node.js web framework with pass-through routing.
       - **Fastify**: High-throughput Node.js framework with pass-through routing.
    3. **Deployment Target / Preset**:
       - **Node Server** (`node-server`, `node-cluster`): Standard Node.js environments.
       - **Serverless & Edge**: `cloudflare-module`, `vercel`, `aws-lambda`, `netlify`.
       - **Runtimes**: `bun`, `deno-server`, `deno-deploy`.
    4. **Schema Validator**:
       - **Zod**: TypeScript-first schema declaration and validation.
       - **ArkType**: TypeScript-native syntax with runtime performance.
       - **Valibot**: Modular, lightweight, tree-shakeable schema library.
    5. **Database / ORM** (Optional):
       - **Drizzle**, **Prisma**, **Kysely**, or None (with SQLite, PostgreSQL, or MySQL drivers).
    6. **Logger** (Optional):
       - **Pino**, **Winston**, or standard Console.

    <Callout type="info" title="Non-Interactive Scaffolding">
      You can also pass CLI flags directly for automated or CI environments:
      ```bash
      pnpm create taserjs@latest my-api --framework none --preset node-server --validator zod --db drizzle --driver sqlite --logger pino -y
      ```
    </Callout>

  </Step>

  <Step>
    ### Start the Development Server

    Navigate to your new project directory, install dependencies, and start the development server:

    <Tabs items={["npm", "pnpm", "yarn", "bun"]}>
      <Tab value="npm">
        ```bash
        cd my-taser-api
        npm install
        npm run dev
        ```
      </Tab>
      <Tab value="pnpm">
        ```bash
        cd my-taser-api
        pnpm install
        pnpm dev
        ```
      </Tab>
      <Tab value="yarn">
        ```bash
        cd my-taser-api
        yarn install
        yarn dev
        ```
      </Tab>
      <Tab value="bun">
        ```bash
        cd my-taser-api
        bun install
        bun dev
        ```
      </Tab>
    </Tabs>

    The development server starts with Vite. Route changes inside `src/routes/` are updated virtually with instant HMR and ambient TypeScript definitions written to `.taser/types/`.

  </Step>
</Steps>

## Project Structure Overview

A freshly scaffolded Taser project contains a clean, modern layout:

```
my-taser-api/
├── package.json
├── tsconfig.json
├── vite.config.ts             # Vite configuration with @taserjs/router-plugin
├── nitro.config.ts            # Nitro deployment presets and server config
├── src/
│   ├── taser.ts               # App router instance and error boundaries
│   ├── context.ts             # App context (boot singletons and request state)
│   ├── server.ts              # Optional host framework entry (Hono/Express/Fastify)
│   └── routes/                # File-based routes directory
│       ├── $.ts               # Root layout middleware (global CORS/security)
│       └── index.get.ts       # GET / endpoint handler
└── .taser/                    # Generated ambient types and build artifacts (gitignored)
```

### Key Files Explained

- **`vite.config.ts`**: Connects the `taser()` plugin from `@taserjs/router-plugin/vite` and `nitro()` for zero-config builds.
- **`nitro.config.ts`**: Configures your production deployment preset (e.g. `node-server`, `cloudflare-module`, `vercel`).
- **`src/taser.ts`**: Configures the `createTaserApp()` instance, error boundaries (`.onError()`), and context binding.
- **`src/context.ts`**: Defines dependency singletons (database, Redis, loggers) and request-scoped metadata.
- **`src/routes/`**: Contains your API endpoints and layout middleware.
- **`.taser/`**: Contains auto-generated ambient TypeScript types (`.taser/types/`) so your editor provides full route autocomplete.

## Add Your First Route

To create a new endpoint, add a file in the `src/routes/` directory.

Create `src/routes/hello.get.ts`:

```ts title="src/routes/hello.get.ts"
import { json } from "@taserjs/router/reply";
import { z } from "zod";
import { t } from "#taserjs/router";

const GET = t
  .get("/hello")
  .query(
    z.object({
      name: z.string().default("World"),
    }),
  )
  .returns({
    200: z.object({
      message: z.string(),
      timestamp: z.string(),
    }),
  });

export type RouteContext = typeof GET.$Infer.Context;
export const Route = GET.handler((ctx) => {
  return json({
    message: `Hello, ${ctx.query.name}!`,
    timestamp: new Date().toISOString(),
  });
});
```

Save the file. Vite hot-reloads the new route immediately without restarting the dev server.

Test your new endpoint in another terminal or browser:

```bash
curl http://localhost:3000/hello?name=Taser
```

Response:

```json
{
  "message": "Hello, Taser!",
  "timestamp": "2026-08-25T00:00:00.000Z"
}
```

<Callout type="info" title="Automatic Boilerplate Generation">
  When you create a new empty route file (e.g. `touch src/routes/users/$id.get.ts`), Vite or `npx taser generate` automatically fills it with type-safe starter boilerplate.
</Callout>
