The quickest way to get started with Taser is using the official `create-taserjs` scaffolding tool. It generates a pre-configured, production-ready project with TypeScript, hot-reloading, route watching, and your choice of tools.

---

## Prerequisites

Before creating a project, make sure your development environment meets these requirements:

- **Node.js**: Version `20.19.0` or higher
- **Package Manager**: `npm`, `pnpm`, `yarn`, or `bun`
- **TypeScript**: Version `5.0` or higher

---

## Create a New Project

<Steps>
  <Step>
    ### Run the Scaffolding Command

    Run the interactive initializer in your terminal:

    <Tabs items={["npm", "pnpm", "yarn", "bun"]}>
      <Tab value="npm">
        ```bash
        npm create taserjs@latest
        ```
      </Tab>
      <Tab value="pnpm">
        ```bash
        pnpm create taserjs
        ```
      </Tab>
      <Tab value="yarn">
        ```bash
        yarn create taserjs
        ```
      </Tab>
      <Tab value="bun">
        ```bash
        bun create taserjs
        ```
      </Tab>
    </Tabs>

  </Step>

  <Step>
    ### Choose Your Stack

    The interactive wizard will guide you through selecting your preferred tools:

    1. **Project Name**: Enter a directory name (for example, `my-taser-api`).
    2. **Runtime / Framework**:
       - **Express**: Battle-tested Node.js web framework.
       - **Fastify**: High-throughput server with low overhead.
       - **Hono**: Lightweight, ultra-fast web standard framework for Node and edge.
       - **Node HTTP**: Plain Node.js native server without extra framework dependencies.
       - **Bun / Deno**: Modern JavaScript runtimes.
       - **Cloudflare Workers / AWS Lambda**: Serverless and edge platforms.
    3. **Schema Validator**:
       - **Zod**: TypeScript-first schema declaration and validation.
       - **ArkType**: TypeScript-native syntax with runtime performance.
       - **Valibot**: Modular, lightweight, tree-shakeable schema library.
    4. **Database / ORM** (Optional):
       - **Prisma**, **Drizzle**, **Kysely**, or None.
    5. **Logger** (Optional):
       - **Pino**, **Winston**, or standard Console.

  </Step>

  <Step>
    ### Start the Development Server

    Navigate to your new project directory, install dependencies, and start the development server:

    <Tabs items={["npm", "pnpm", "yarn", "bun"]}>
      <Tab value="npm">
        ```bash
        cd my-taser-api
        npm install
        npm run dev
        ```
      </Tab>
      <Tab value="pnpm">
        ```bash
        cd my-taser-api
        pnpm install
        pnpm dev
        ```
      </Tab>
      <Tab value="yarn">
        ```bash
        cd my-taser-api
        yarn install
        yarn dev
        ```
      </Tab>
      <Tab value="bun">
        ```bash
        cd my-taser-api
        bun install
        bun dev
        ```
      </Tab>
    </Tabs>

    The development server starts with `@taserjs/router-cli` in watch mode. Any changes to files inside `src/routes/` automatically regenerate the route manifest.

  </Step>
</Steps>

## Project Structure Overview

A freshly scaffolded Taser project contains a clean, modular structure:

```
my-taser-api/
├── package.json
├── tsconfig.json
├── taser.config.json          # CLI and codegen configuration
├── src/
│   ├── index.ts               # Server entry point (mounts Taser app)
│   ├── taser.ts               # App router instance and error handlers
│   ├── context.ts             # App context (boot and request scoped state)
│   ├── routeManifest.gen.ts   # Auto-generated route manifest (do not edit)
│   └── routes/                # File-based routes directory
│       ├── $.ts               # Root layout middleware (global CORS/auth)
│       └── index.get.ts       # GET / endpoint handler
```

### Key Files Explained

- **`src/context.ts`**: Defines dependencies and request-scoped metadata injected into your routes.
- **`src/taser.ts`**: Configures the `createTaserApp()` builder, binds global error handlers (`.onError()`), and attaches context.
- **`src/routes/`**: Contains your API endpoints and layout middleware. File names determine HTTP methods and URL paths.
- **`src/routeManifest.gen.ts`**: Generated by the CLI. Maps files to runtime routes with full type inference.

## Add Your First Route

To create a new endpoint, add a file in the `src/routes/` directory.

Create `src/routes/hello.get.ts`:

```ts title="src/routes/hello.get.ts"
import { reply } from "@taserjs/router";
import { z } from "zod";
import { t } from "../taser";

export const Route = t
  .get("/hello", {
    query: z.object({
      name: z.string().default("World"),
    }),
  })
  .returns({
    200: z.object({
      message: z.string(),
      timestamp: z.string(),
    }),
  })
  .handler((ctx) => {
    return reply.json({
      message: `Hello, ${ctx.query.name}!`,
      timestamp: new Date().toISOString(),
    });
  });
```

Save the file. The CLI watch process immediately updates `routeManifest.gen.ts`.

Test your new endpoint in another terminal or browser:

```bash
curl http://localhost:3000/hello?name=Taser
```

Response:

```json
{
  "message": "Hello, Taser!",
  "timestamp": "2026-08-18T00:00:00.000Z"
}
```

<Callout type="info" title="Route Scaffolding CLI">
  You can also create new route files from the command line using `npx taser scaffold
  users/$id.get.ts`.
</Callout>
