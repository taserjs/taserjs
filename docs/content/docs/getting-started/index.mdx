The quickest way to get started with Taser.js is using the official `create-taserjs` scaffolding tool. It generates a pre-configured, production-ready project with TypeScript, hot-reloading, route watching, and your choice of tools.

---

## Prerequisites

Before creating a project, make sure your development environment meets these requirements:

- **Node.js**: Version `20.19.0` or higher
- **Package Manager**: `npm`, `pnpm`, `yarn`, or `bun`
- **TypeScript**: Version `5.0` or higher

---

## Create a New Project

<Steps>
  <Step>
    ### Run the Scaffolding Command

    Run the interactive initializer in your terminal:

    <Tabs items={["pnpm", "npm", "bun", "yarn"]} groupId="package-manager" persist>
      <Tab value="pnpm">
        ```bash
        pnpm create taserjs@latest
        ```
      </Tab>
      <Tab value="npm">
        ```bash
        npm create taserjs@latest
        ```
      </Tab>
      <Tab value="bun">
        ```bash
        bun create taserjs@latest
        ```
      </Tab>
      <Tab value="yarn">
        ```bash
        yarn create taserjs
        ```
      </Tab>
    </Tabs>

  </Step>

  <Step>
    ### Choose Your Stack

    The interactive wizard guides you through:

    1. **Project Name**: Enter a directory name (for example, `my-taser-app`).
    2. **Base framework**:
       - **API only**: A standalone Taser.js server with no UI.
       - **TanStack Router** or **Vite**: A single-page UI on Vite, served together with your API. Vite asks for a template: **React**, **Vue**, **Svelte**, **Solid** or **Preact**.
       - **React Router**, **TanStack Start**, **Next.js**, **Nuxt** or **SvelteKit**: A fullstack framework that owns the server, with Taser.js mounted under `/api`.
    3. **Deployment** (skipped for frameworks that deploy through their own adapter, such as Next.js, Nuxt, SvelteKit and React Router):
       - **None**: Runs on Node.js. Build with `vite build` and start with `node .output/server/index.mjs`.
       - **Cloudflare Workers**, **Vercel**, **Netlify** or **AWS Lambda**: Deploy through the matching Nitro preset.
       - Every project that picks a deployment installs `nitro`, which also serves the built UI next to the API for Vite web apps.
    4. **Schema Validator** (Optional): **Zod**, **Valibot**, or **ArkType**.
    5. **Database / ORM** (Optional): **Drizzle**, **Prisma**, or **Kysely** with a `sqlite`, `postgres`, or `mysql` driver.
    6. **Logger** (Optional): **Pino** or **Winston**.

    UI projects are created by running the framework's official generator (`create-vite`, `create-next-app`, `@tanstack/cli`) at `@latest`, then adding Taser.js on top. Taser.js adds its packages, wires `taser()` into your Vite config (or `createTaser()` into `next.config.ts`), and creates `src/server/` for your API and `src/api.ts` with a typed client. It does not change your components. If a config file has an unexpected shape, the wizard prints the lines to add by hand.

    <Callout type="info" title="Runtime is not a scaffold choice">
      Taser.js runs on Node.js, Bun, and Deno. The scaffolder does not configure a runtime; run the generated build with the runtime you prefer.
    </Callout>

    <Callout type="info" title="Non-Interactive Scaffolding">
      You can pass CLI flags directly for automated or CI environments:
      ```bash
      pnpm create taserjs@latest my-api \
        --framework none \
        --preset node-server \
        --db drizzle \
        --driver postgres \
        --validator zod \
        --logger pino \
        -y
      ```
    </Callout>

    ### CLI Flags Reference

    | Flag | Description | Values | Default |
    | :--- | :--- | :--- | :--- |
    | `--framework`, `-f` | UI or fullstack framework | `none` (API only), `tanstack-router`, `react-router`, `tanstack-start`, `nextjs`, `nuxt`, `sveltekit`, `vite` | `none` |
    | `--template`, `-t` | Template for `vite` projects, passed to `create-vite` as the TypeScript variant | `react`, `vue`, `svelte`, `solid`, `preact` | `react` |
    | `--preset`, `-p` | Nitro preset to deploy with, see [Nitro presets](https://nitro.build/deploy) | `node-server`, `cloudflare-module`, `vercel`, `netlify`, `aws-lambda`, or another Nitro preset | `node-server` |
    | `--host` | Existing server framework that receives requests no Taser.js route matches | `none`, `express`, `fastify`, `hono`, `elysia` | `none` |
    | `--db` | Database ORM / query builder | `drizzle`, `prisma`, `kysely`, `none` | `none` |
    | `--driver` | Database driver (with `--db`) | `sqlite`, `postgres`, `mysql` | `sqlite` |
    | `--validator`, `-v` | Schema validation library | `zod`, `valibot`, `arktype`, `none` | `none` |
    | `--logger`, `-l` | Structured logger | `pino`, `winston`, `none` | `none` |
    | `--skip-install` | Skip automatic package installation | `boolean` | `false` |
    | `-y`, `--yes` | Non-interactive mode using defaults for omitted flags | `boolean` | `false` |

    `--preset` does not apply to `nextjs`, `nuxt`, `sveltekit` or `react-router`, which deploy through their own adapter or Nitro preset.

    `--host` applies to API-only, `tanstack-router` and `vite` projects. It writes `server.node.ts` (Express, Fastify) or `server.ts` (Hono, Elysia) into the server directory. Express and Fastify need Node.js APIs, so they cannot be combined with the Cloudflare presets. `nextjs`, `tanstack-start`, `nuxt`, `sveltekit` and `react-router` own their server and reject `--host`.

    #### Where Files Go

    - **API only**: `serverDir` is `src` (`src/taser.ts`, `src/routes/`).
    - **UI projects**: `serverDir` is `src/server`, with `defineTaser().basePath("/api")`. Database, logger, and validator files live there too (for example `src/server/db/`).

  </Step>

  <Step>
    ### Start the Development Server

    Navigate to your new project directory, install dependencies, and start the development server:

    <Tabs items={["pnpm", "npm", "bun", "yarn"]} groupId="package-manager" persist>
      <Tab value="pnpm">
        ```bash
        cd my-taser-api
        pnpm install
        pnpm dev
        ```
      </Tab>
      <Tab value="npm">
        ```bash
        cd my-taser-api
        npm install
        npm run dev
        ```
      </Tab>
      <Tab value="bun">
        ```bash
        cd my-taser-api
        bun install
        bun dev
        ```
      </Tab>
      <Tab value="yarn">
        ```bash
        cd my-taser-api
        yarn install
        yarn dev
        ```
      </Tab>
    </Tabs>

    The development server starts with Vite. Route changes inside `src/routes/` are updated virtually with instant HMR, and the unified manifest is written to `src/.taserjs/routes.gen.ts`.

  </Step>
</Steps>

## Project Structure Overview

A freshly scaffolded Taser.js project contains a clean, modern layout:

<Files>
  <Folder name="my-taser-api" defaultOpen>
    <File name="package.json" />
    <File name="tsconfig.json" />
    <File name="vite.config.ts" />
    <File name="taserjs.config.ts" />
    <Folder name="src" defaultOpen>
      <File name="taser.ts" />
      <File name="context.ts" />
      <Folder name="routes" defaultOpen>
        <File name="$.ts" route="/*" />
        <File name="index.get.ts" route="/" />
        <File name="health.get.ts" route="/health" />
      </Folder>
      <Folder name=".taserjs" defaultOpen>
        <File name="routes.gen.ts" />
      </Folder>
    </Folder>
  </Folder>
</Files>

### Key Files Explained

- **`vite.config.ts`**: Connects the `taser()` plugin from `@taserjs/plugin/vite` and `nitro()` for zero-config builds (or pure Vite in standalone `none` preset).
- **`nitro.config.ts`** _(conditional)_: Generated when targeting non-default deployment presets (e.g. `cloudflare-module`, `vercel`, `aws-lambda`, `netlify`). Omitted for default `node-server` and standalone `none`.
- **`src/server.ts` / `src/server.node.ts`** _(conditional)_: Generated when a host framework is configured (`src/server.ts` for Hono, `src/server.node.ts` for Express or Fastify).
- **`src/taser.ts`**: Exports `defineTaser()` configuration (`TaserDefinition`) — context, `.onError()`, `.notFound()`, and response options. Does not instantiate the Hono app.

  ```ts title="src/taser.ts"
  import { defineTaser } from "@taserjs/router";
  import { context } from "./context.js";

  export default defineTaser({
    response: { validate: true },
  }).context(context);
  ```

- **`src/context.ts`**: Defines application singletons (database, logger, external services) and request-scoped context.
- **`src/routes/`**: Contains your API endpoints (`index.get.ts`, `health.get.ts`) and root layout middleware (`$.ts`).
- **`src/.taserjs/routes.gen.ts`**: Generated unified entry exporting the runnable `app`, ambient route types, and `AppManifest` for `@taserjs/client`.

## Add Your First Route

To create a new endpoint, add a file in the `src/routes/` directory.

Create `src/routes/hello.get.ts`:

```ts title="src/routes/hello.get.ts"
import { json } from "@taserjs/router/reply";
import { t } from "@taserjs/router";

export default t.get("/hello").handler(() => {
  return json({
    message: "Hello from Taser.js!",
    timestamp: new Date().toISOString(),
  });
});
```

Save the file. Vite hot-reloads the new route immediately without restarting the dev server.

Test your new endpoint in another terminal or browser:

```bash
curl http://localhost:3000/hello
```

Response:

```json
{
  "message": "Hello from Taser.js!",
  "timestamp": "2026-08-25T00:00:00.000Z"
}
```

<Callout type="info" title="Route Path Strings Are Generated Automatically">
  The path string passed to `t.get()`, `t.post()`, `t.layout()`, etc. is generated automatically by
  the dev watcher (`vite dev`, `next dev`) or `@taserjs/cli` when route files are first created
  (e.g. via `touch src/routes/...`). You do not need to author this string by hand.
</Callout>
