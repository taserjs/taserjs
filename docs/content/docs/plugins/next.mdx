The `@taserjs/plugin/next` package hooks Taser.js into Next.js 15+ App Router builds. It generates `src/server/.taserjs/routes.gen.ts` (path follows your `serverDir`) and wires Webpack/Turbopack so routes stay in sync during `next dev` and `next build`.

<Callout type="info" title="Looking for the Fullstack Next.js Guide?">
  For RSC patterns and Server Actions recipes, see the [Next.js App Router Fullstack
  Guide](/docs/fullstack/nextjs).
</Callout>

## Installation

Install `@taserjs/plugin` and `@taserjs/cli` as development dependencies:

<Tabs items={["pnpm", "npm", "bun", "yarn"]} groupId="package-manager" persist>
  <Tab value="pnpm">
    ```bash
    pnpm add -D @taserjs/plugin @taserjs/cli
    ```
  </Tab>
  <Tab value="npm">
    ```bash
    npm install -D @taserjs/plugin @taserjs/cli
    ```
  </Tab>
  <Tab value="bun">
    ```bash
    bun add -d @taserjs/plugin @taserjs/cli
    ```
  </Tab>
  <Tab value="yarn">
    ```bash
    yarn add -D @taserjs/plugin @taserjs/cli
    ```
  </Tab>
</Tabs>

Prefer a `taserjs.config.ts` for shared path settings:

```ts title="taserjs.config.ts"
import { defineConfig } from "@taserjs/cli";

export default defineConfig({
  serverDir: "src/server",
  routesDir: "routes",
  outputDir: ".taserjs",
  app: "taser.ts",
});
```

## Basic Configuration

Wrap `next.config.ts` with `createTaser` (or `withTaser`):

```ts title="next.config.ts"
import type { NextConfig } from "next";
import { createTaser } from "@taserjs/plugin/next";

const nextConfig: NextConfig = {
  reactStrictMode: true,
};

const withTaser = createTaser({
  serverDir: "src/server",
});

export default withTaser(nextConfig);
```

Function-style Next config also works:

```ts title="next.config.ts"
import { withTaser } from "@taserjs/plugin/next";

export default withTaser(
  {
    reactStrictMode: true,
  },
  {
    serverDir: "src/server",
  },
);
```

Set the HTTP mount with `defineTaser().basePath("/api")` in `src/server/taser.ts`, and point the client `baseUrl` at the same prefix (for example `"/api"`).

## Plugin Options

`createTaser` accepts `NextTaserOptions` (extends shared plugin options):

```ts title="next.config.ts"
const withTaser = createTaser({
  serverDir: "src/server",
  config: "./taserjs.config.ts",
  extension: false,
});
```

<TypeTable
  type={{
    serverDir: {
      description:
        "Server root containing the app file and routes folder. Overrides taserjs.config.ts when set.",
      type: "string",
      default: "from taserjs.config.ts ('src')",
    },
    basePath: {
      description:
        "Optional URL prefix metadata for tooling. Prefer defineTaser().basePath() for runtime mounting and client baseUrl for requests.",
      type: "string",
      default: "undefined",
    },
    extension: {
      description: "Import extension style written into generated routes.gen.ts.",
      type: "boolean | string",
      default: "from taserjs.config.ts",
    },
    config: {
      description: "Path to taserjs.config.ts (or .js/.mjs/.cjs).",
      type: "string",
      default: "undefined",
    },
    cwd: {
      description: "Project root used when resolving config and paths.",
      type: "string",
      default: "process.cwd()",
    },
    serverEntry: {
      description: "Optional host server entry path (alias: serverEntryPath).",
      type: "string",
      default: "undefined",
    },
    server: {
      description: "Shared plugin flag; Next uses generation + Webpack/Turbopack hooks instead of Vite middleware.",
      type: "boolean",
      default: "true",
    },
  }}
/>

`routesDir` and `outputDir` come from [`taserjs.config.ts`](/docs/cli) (defaults `routes` and `.taserjs` under `serverDir`).

---

## How It Works

1. **Watches `${serverDir}/routes/`** during `next dev` and regenerates on change (with scaffolding for empty files).
2. **Writes `${serverDir}/.taserjs/routes.gen.ts`**: compiled `app`, ambient route types, and the composite manifest for `@taserjs/client`.
3. **Hooks Webpack** (and keeps Turbopack in sync via the watcher) so builds always see a fresh manifest.
