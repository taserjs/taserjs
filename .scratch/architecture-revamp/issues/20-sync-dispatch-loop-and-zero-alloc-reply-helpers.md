# 20: Synchronous Dispatch Loop, Zero-Alloc Reply Helpers, and Dirty-Checked Cookie Flushing

Status: completed
Type: enhancement
Blocked by: 19

## Agent Brief

**Category:** enhancement
**Summary:** Close the remaining ~1.5x throughput gap between `@taserjs/runtime` and native Hono by removing forced async/Promise allocations on synchronous route execution, optimizing `@taserjs/utils` reply helpers (`json()`) to avoid `new Headers()` and `Object.defineProperty()`, caching frozen empty state objects, and introducing dirty-tracking in `TaserCookieJar`.

**Current behavior:**
While Issue #19 raised Taser's baseline GET throughput from ~40k req/s to ~63k req/s and slashed parameter/validation overhead, Taser is still ~1.3x–1.5x slower than bare Hono on hot routes (e.g., plain route ~63k req/s vs ~92k req/s, cookies ~20k req/s vs ~40k req/s).
Root-cause analysis and profiling identified 4 primary areas with remaining overhead:
1. **Unconditional `async` Hono handler callback (`app.on`)**: In `app.ts`, `app.on(method, targetPath, async (c) => ...)` forces V8 to allocate a `Promise` instance and schedule a microtask tick on every request even when the route handler and pipeline execute completely synchronously. Bare Hono routes return `Response` synchronously, bypassing Promise resolution entirely.
2. **`json()` reply helper overhead (`packages/utils/src/reply.ts`)**: Every call to `json(data)` instantiates a Web standard `new Headers()` object and calls `Object.defineProperty(...)` twice on the `Response` instance to attach `_data` and `_status`, de-optimizing V8 hidden class transitions.
3. **Redundant Cookie flushing (`TaserCookieJar.flush`)**: `cookie()` middleware always runs `jar.flush(res)` upon request return, calling `c.res?.headers?.getSetCookie()` and string parsing even when no cookies were set or deleted (e.g. read-only requests).
4. **Transient object allocations**: Handler arguments allocate fresh empty objects `{}` for `state` when no middleware provided state.

**Desired behavior:**

1. **Synchronous Execution Loop in `app.on` and `createPipeline`**:
   - In `app.ts`, don't mark the route callback `async`.
   - Synchronously invoke `pipeline(req, ctx)`. If the return value is not a Promise (`!(res instanceof Promise)`), return the `Response` directly to Hono.
   - If the return value is a Promise (async middleware or async handler), await/then it before returning.
   - Support synchronous execution in `pipeline.ts` for synchronous terminal handlers and synchronous middlewares.
2. **Fast-Path for `json()` and `text()` in `@taserjs/utils`**:
   - When `init === undefined`, reuse a static frozen headers dictionary (`{ "content-type": "application/json; charset=utf-8" }`).
   - Assign `_data` and `_status` directly as property assignments (`res._data = data; res._status = 200;`) instead of `Object.defineProperty()`.
   - Maintain the identical `TypedResponse` interface and behavior.
3. **Dirty-Checking in `TaserCookieJar`**:
   - Add a private `#dirty` boolean to `TaserCookieJar`.
   - Set `#dirty = true` only when `.set()`, `.delete()`, or `.setSigned()` is called.
   - In `flush(res)`, if `!this.#dirty`, return `res` immediately without accessing `c.res` or cookie headers.
4. **Frozen `EMPTY_STATE` Sharing**:
   - Share a static `EMPTY_STATE = Object.freeze({})` for route handlers and middlewares that do not receive state from upstream.
5. **Benchmark Verification**:
   - Run `pnpm bench` to confirm throughput increases across plain routes, route middlewares, cookie handling, and body validation, moving Taser to within ~5–10% of native Hono throughput.

**Key interfaces:**

- `createTaserApp` in `packages/runtime/src/app.ts`
- `createPipeline`, `invokeTerminalHandler` in `packages/runtime/src/pipeline.ts`
- `json`, `createTypedResponse` in `packages/utils/src/reply.ts`
- `TaserCookieJar`, `cookie` in `packages/router/src/cookie.ts`

**Acceptance criteria:**

- [x] Baseline GET benchmark throughput increases towards ~85k–90k req/s (matching native Hono within ~5–10%).
- [x] Cookie middleware throughput on read-only requests increases significantly due to dirty-checking bypass.
- [x] Response helper `json()` executes without `new Headers()` or `Object.defineProperty()` on default options.
- [x] All unit and integration tests (`pnpm test`) pass with 0 regressions.
- [x] Typecheck (`pnpm typecheck`) and lint (`pnpm lint`) pass cleanly across the monorepo.

**Out of scope:**

- Changing the external signature or type definition of `TypedResponse`.
- Bypassing Hono's route matching or `Context` abstraction.
